ANDRIK R1546 — D1 READ ECONOMY (без изменений VPS)

Исправления в _worker.js:
1. Фоновый Cron MUSIC/SOCIAL не выполняет CREATE TABLE IF NOT EXISTS при каждом запуске. Таблица создаётся только при первом запуске.
2. Когда оба фоновых отчёта свежее 6 часов, Cron завершает работу без повторного пересчёта MANAGER. MANAGER продолжает обновляться по отчётам WATCH/GUARD и по запросу контрольки.
3. Фоновый SOCIAL получает последний снимок по ORDER BY created_at DESC, используя существующий индекс idx_platform_snapshots_platform_created, вместо ORDER BY datetime(created_at).
4. При запросе MANAGER фоновая таблица больше не создаётся повторно на каждом обновлении.

Не изменено: OneSignal, push, WATCH, GUARD, расписание VPS, радио, история клипов.

ВАЖНО: это адресная экономия запросов, не гарантия решения лимита 5 млн rows_read. Для поиска главного источника требуется Cloudflare D1 Analytics / Query insights (rows read по запросам). Код не может узнать реальные счётчики D1 без телеметрии Cloudflare.

Установка: контролька -> Обновить сайт -> загрузить весь ZIP. VPS не перезапускать.
