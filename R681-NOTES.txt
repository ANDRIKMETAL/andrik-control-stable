R681 — D1 ECONOMY / FREE-TIER PROTECTION

Goal: cut continuous D1 writes before Cloudflare Free daily limits are enforced for this account.

Safe changes:
1) OVH radio agent keeps polling every 4s for command latency, but persists heartbeat only every 30s or when radio status/version changes.
   - Before: up to 21,600 heartbeat UPDATEs/day per agent.
   - After: about 2,880 heartbeat UPDATEs/day per continuously healthy agent, plus real status changes.
   - Control ONLINE timeout widened to 75s to match persisted heartbeat cadence.
2) Healthy 2-minute YouTube fast-check success is no longer inserted into system_logs every cycle.
   Warnings/errors are still logged.
3) Routine legacy external cron success rows are no longer inserted into system_logs.
   Warnings/errors are still logged.
4) Removed the transient youtube-fast-engagement='running' D1 write every 2 minutes.
5) Observed YouTube like counters are persisted only when a counter actually changes.
6) Current LIVE video key is persisted only when the live video changes.
7) LIVE-chat seeded marker is written once; page token is written only when it changes.

Not changed:
- YouTube/OneSignal push delivery
- 2-minute reaction checking cadence
- Radio command poll cadence
- Radio stream/OVH/FFmpeg
- Search Console / Analytics UI
- R680 admin swipe target
- Existing D1 history/data

Important: exact Cloudflare account row-read/row-write usage must still be verified in Cloudflare Dashboard > Billing > Billable Usage or D1 > Metrics > Row Metrics.
