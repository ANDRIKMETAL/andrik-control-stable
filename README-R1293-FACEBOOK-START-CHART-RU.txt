ANDRIK SITE R1293 — ЕЖЕДНЕВНЫЙ START FACEBOOK 14:00 + ОБЪЁМНЫЙ ГРАФИК
БАЗА: Полный ANDRIK SITE R1292, основанный на R1291.
Дата сборки: 12 октября 2026.

ВАЖНО: планировщик НЕ запускает Facebook немедленно после установки.
При чистой настройке он выключен. Если на сайте R1292 расписание уже было включено,
состояние в Cloudflare D1 сохраняется; проверь переключатель после установки.

ЧТО ИЗМЕНЕНО
1) В разделе Facebook полностью удалена плитка «Смотрят сейчас» — Meta не раскрывает
проверенную цифру для профессионального профиля через доступный Graph API.
2) Сохранены реальные video.views и live_status, а также история опросов в Cloudflare D1.
Вместо онлайна появился прирост просмотров за выбранный период.
3) Новый объёмный бирюзовый график: линия = накопленные video.views,
столбики = положительные разницы между соседними реальными замерами.
Нет фальшивых людей, нулей вместо отсутствующих данных, или подстановок RTMPS TCP.
Периоды: 1 час, 6 часов, 24 часа, весь эфир. История до 1600 замеров.
4) Facebook ежедневно: только один автоматический START в 14:00 Europe/Bratislava.
Локальный часовой пояс обрабатывает CET/CEST автоматически.
5) ПОЛНОСТЬЮ УДАЛЕНЫ scheduled auto STOP через 475 минут и прежний auto STOP
при изменении статуса Meta. Планировщик вообще не ставит STOP в очередь.
6) Отдельные ручные START и STOP сохранены; YouTube/master radio не меняются.
7) На месте прежних двух специальных API-адресов остаются совместимые
/api/control/facebook-schedule-r1292 и /api/control/facebook-meta-r1292,
поэтому старые настройки Cloudflare D1 и токена META_USER_ACCESS_TOKEN_R1292
продолжают работать. Новых секретов не добавлено.

ПРЕДУПРЕЖДЕНИЕ META
По расписанию стартует ТОЛЬКО исходящая RTMPS-передача с VPS.
Создание Facebook-публикации с названием/описанием и действие Go Live
не реализованы для профессионального профиля: право publish_video не выдано.
Создай/подготовь мероприятие и название/описание в Live Producer, проверь
возможность автоматической публикации у Meta. RTMPS-сигнал сам по себе НЕ
гарантирует видимый зрителям эфир каждый новый день.
Если Meta завершает эфир, этот планировщик не делает STOP; повторные
подключения регулируются существующей защитой Facebook на VPS (R1279).
Если на следующий день Facebook FFmpeg всё ещё идёт, старт пропускается,
чтобы не прерывать действующую или ручную трансляцию.

КАК ВКЛЮЧИТЬ
1. Сохранить предыдущую полную версию R1292 как backup.
2. Загрузить полный ZIP R1293 в тот же Cloudflare Pages проект обычным способом;
   патч ZIP подходит только если уже установлен сайт R1292.
3. Проверить /radio-facebook-admin.html, что новый блок показывает
   «14:00» и «Окончание: не планируется».
4. Убедиться, что Cron Gateway жив: в статусе показан свежий heartbeat.
   Для более точного старта подходящий Cron Trigger должен запускаться
   каждую минуту или как минимум каждые пять минут; приложение допускает
   задержку проверки до 15 минут после 14:00.
5. Подготовить в Meta Live Producer мероприятие, вставив название/описание
   из раскрывающегося блока (автоматическая вставка НЕ подтверждена).
6. Отметить «Эфир подготовлен в Meta» и «Включить ежедневное расписание»,
   нажать «Сохранить расписание».
7. Для графика сохранить личный User Access Token ANDRIK Control в
   Cloudflare Pages/Worker секретах META_USER_ACCESS_TOKEN_R1292.
   NEVER класть токен в HTML или публичный ZIP.
8. Ввести Live Video ID актуального эфира для статистики. При новом эфире
   Meta может выдавать новый ID; прежняя история не должна переноситься.

ОГРАНИЧЕНИЕ ПРОВЕРКИ
Синтаксис _worker.js и встроенного JS проверен локально; сценарий
планировщика проверен с эмуляцией Cron в 14:00, 14:01 и 22:00.
Реальный Facebook Go Live, доступ Meta и конфигурация Cron на хостинге
не проверены. Изменение на VPS/YouTube не вносилось.
ОТКАТ: развернуть резервную версию R1292 и в ней отключить расписание.
