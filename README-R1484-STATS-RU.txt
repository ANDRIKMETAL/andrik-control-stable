ANDRIK METAL — R1484 · СТАТИСТИКА И ГРАФИКИ
Эфир: https://www.youtube.com/live/U0bzXBNBs2Y

УСТАНОВКА
Загрузи SITE-R1484-INSTALL.zip в обычное обновление сайта в контрольке.
Это полный установочный архив, распаковывать его перед загрузкой не нужно.
Внешней папки внутри ZIP нет. Файлы лежат прямо в корне.
После успешного обновления открой заново раздел «Стрим YouTube».
В заголовке должна быть версия R1484. Перезапускать эфир для этой правки не требуется.

ЧТО ИСПРАВЛЕНО
1. Счётчики запрашиваются через отдельный обработчик /api/control/radio-metrics-r1484.
   Он получает statistics и liveStreamingDetails из videos.list и сохраняет
   доступные цифры до дополнительных попыток авторизации.
   Запросы Studio, отчётов Analytics и разбор страниц YouTube его не задерживают.
2. При ошибке API-ключа используется существующее подключение OAuth владельца.
   Если ключ вернул просмотры, но не онлайн, они сразу записываются; затем
   OAuth пробуется отдельно для заполнения недостающего числа зрителей.
3. Сбор текущего эфира не зависит от старого YOUTUBE_CHANNEL_ID, поиска канала
   или успешности уведомлений. Другой ID видео не принимается.
4. Cron gateway запускает отдельную задачу сбора. Она использует уже настроенный
   Cron Trigger, отдельный двухминутный слот и не требует открытой контрольки.
   Если самого Cron Trigger нет, архив не может создать его в Cloudflare;
   при открытой контрольке замеры также записываются запросами статистики.
5. Просмотры, зрители онлайн, лайки, время и результат записи показываются явно.
   Ошибка API или базы не скрывается за зелёным статусом передачи сигнала.
   При ошибке OAuth есть ссылка на существующий раздел авторизации YouTube.
6. Настоящий ноль остаётся нулём. Отсутствующее значение остаётся неизвестным.
   При ошибке обновления старые цифры не выдаются за новые.
   Старый браузерный кеш не заменяет свежий ответ API.
7. Пустой график различает ошибку сбора, ожидание первого замера,
   отсутствие онлайн в ответе API и выбранный участок времени без данных.
   При отсутствии замеров пик просмотров показывается прочерком, а не +0.
8. Сохранены компактный календарь и счётчики R1483, увеличение графиков,
   интервалы 1/3/6 часов и день, изменение масштаба и перемещение по оси X,
   нажатие на точку с точным временем, корректные 23- и 25-часовые дни.
9. Новые имена JS и версия кеша позволяют загрузить исправленные файлы.
   Серверные обработчики запуска, остановки и управления эфиром сохранены.

КАК ЧИТАТЬ ЦИФРЫ
«Просмотры LIVE · API» — суммарный viewCount выбранного эфира.
«Новые по API · сегодня» — наблюдаемый прирост между сохранёнными замерами,
а не число уникальных людей. Первый доступный замер устанавливает базу.
Зрители онлайн — реальные значения concurrentViewers из ответа YouTube.
API может обновлять просмотры с задержкой и иногда не возвращает онлайн.
Статус сигнала и доступность статистики показываются отдельно.
Прошлый час без записанных замеров не восстанавливается искусственно.

ПРОВЕРКА ПЕРЕД ВЫДАЧЕЙ
Проверены синтаксис worker и клиентов, реальные SQL-запросы на SQLite-адаптере,
авторизация обработчиков, резервный OAuth, нули и отсутствующие значения,
отказ API и записи, защита от другого ID, завершённый эфир, одновременные
запросы, независимый cron и заполнение данных для графиков.
Исполнены клиентские скрипты с DOM-моделью: ошибки и частичные данные,
общий запрос истории, даты, ось времени, масштаб, панорамирование,
нажатия, увеличение, SVG для разных ширин и переходы летнего времени.
Проверены CRC, SHA каждого файла и обработка ZIP установщиком.
Для совместимости установочный ZIP использует STORE, без сжатия файлов.

ВАЖНО О ПРОВЕРКЕ
Ответы YouTube в этих проверках были подставными. Доступ к реальным секретам
Cloudflare и авторизации владельца не использовался. Если действующий ключ,
OAuth или привязка базы не работают, контролька покажет конкретную причину.
Успешные локальные проверки не подтверждают действительность этих настроек.
