ANDRIK Control R326
Base: user-confirmed working R325.

ROOT CAUSE FOUND:
handleMusicDownloadsR322 returned json(data, {headers: ...}).
The project json() helper signature is json(data, status=200, headers=JSON_HEADERS),
so the object was passed as HTTP status. The /api/music/downloads endpoint therefore failed,
and the player intentionally kept the MP3 button hidden.

FIXES:
- /api/music/downloads now returns valid JSON with HTTP 200/no-store.
- Player MP3 script moved to fresh R326 asset path to bypass stale cache.
- Matching uses R2 metadata title + album.
- Added album + track-number fallback from playlist position (e.g. OCEAN 2/10 -> R2 track 2),
  so Russian/English/title formatting differences cannot hide the download button.
- Endpoint retries up to 3 times if temporarily unavailable.
- Refreshes mapping on pageshow/focus.

SAFETY:
- R325 WAV/OPFS staging and Cancel All retained.
- admin-sections/comments/service/observability unchanged byte-for-byte.
- YouTube player engine unchanged.
