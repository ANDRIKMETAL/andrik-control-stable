ANDRIK R1522 — безопасное присоединение действующего LIVE к расписанию

ИСПРАВЛЕНИЕ: R1517 создаёт новый LIVE раз в день. Если эфир уже вручную запущен, API отвечает 409 other-youtube-live-in-progress и не сохраняет session/videoId. После успешной повторной OAuth-авторизации ситуация не исправляется сама собой.

R1522 проверяет активную YouTube-трансляцию и присоединяет её к выбранному сеансу, только если:
- в аккаунте YouTube ровно один LIVE;
- текущий эфир привязан к ЕДИНСТВЕННОМУ активному streamId;
- название YouTube LIVE точно совпадает с заголовком сеанса ЛИБО содержит название ANDRIK RADIO, характерный дневной/вечерний маркер и все нужные названия альбомов;
- эфир является публичным.

При совпадении возвращается existing:true, adopted:true и фиксируется YouTube videoId. Тогда VPS R1517 при следующем тике получает session.status=live и при завершении временного окна может выполнить /session/complete для ровно этого videoId.

ВАЖНО: установка R1522 изменяет только сайт/Cloudflare Worker, НЕ перезапускает VPS и не обрывает поток. Но текущий архив YouTube и фактическое завершение в 14:00 всё ещё необходимо проверить по логам. Если заголовок LIVE отличается от заголовка в настройках, автоматическое присоединение не произойдёт: это предохранитель. В этом случае нужно привести заголовки к одному значению, либо завершить текущий LIVE и позволить автоматизации создать новый в следующем окне.

После установки: sudo journalctl -u andrik-radio-schedule-r1517.service -n 25 --no-pager
Ожидается YOUTUBE_SESSION_STARTED с existing:true, затем YOUTUBE_ALREADY_LIVE.
