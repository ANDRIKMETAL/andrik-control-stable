ANDRIK RADIO R1160L · исправление остановки MP3-фона после клипа
Основа: присланный server.mjs R1160J; включает исправления CPU и процессов R1160K.

УСТАНОВКА НА VPS
Загрузи ANDRIK-R1160L-RADIO-FIX.zip в домашнюю папку пользователя VPS.
Выполни:

cd ~
unzip -o ANDRIK-R1160L-RADIO-FIX.zip
cd ANDRIK-R1160L
sudo bash INSTALL-R1160L.sh --apply
sudo bash INSTALL-AGENT-R1183.sh --apply

INSTALL-R1160L.sh сначала проверяет синтаксис и SHA256. Принимаются только точные исходные R1160J и R1160K. При другом server.mjs установка останавливается до изменения эфира — нельзя обходить эту проверку вслепую.
Целевой файл: /opt/andrik-radio/radio247/server.mjs
Служба: andrik-radio.service
При установке сервер радио перезапускается один раз: возможен краткий перерыв.
Резервная копия и ROLLBACK.sh создаются в /opt/andrik-radio/backups/R1160L-*; точный путь выводит установщик. При неуспешной проверке запуска старый файл возвращается автоматически.
INSTALL-AGENT-R1183.sh обновляет /usr/local/lib/andrik-radio-web-agent-r803.mjs и перезапускает только andrik-radio-web-control.service. Резервная копия агента — /root/ANDRIK-SAFE/R1183-agent-*.
Предварительная проверка без изменения файлов: sudo bash INSTALL-R1160L.sh --check

ПРИЧИНА
В присланном журнале MP3-фон продвинут в 18:17:01.824Z. Отсчёт NO-PROGRESS у master указывает на остановку около 18:17:08.779Z — примерно через 7 секунд, когда заканчивается защита первых кадров R1150. Затем срабатывают watchdog relay и publisher; ошибки PPS появляются после восстановления.
В коде R1085 сравнивает отправленные PCM-байты и счётчик отправленных кадров с целью 2000 мс / допуском 80 мс. При недостатке аудио он выбрасывал кадры. Но эти PCM-байты включают заполненную входную очередь. Если аудио уже заблокировано, отбрасывание всех кадров лишает FFmpeg возможности освободить её: возникает замкнутое ожидание. R1160G дополнительно переписывал счётчик кадров после клипа, не меняя сам поток.
Этот механизм воспроизведён локально с реальным FFmpeg и искусственно внесённой ошибкой счётчика. Это сильное совпадение с журналом, а не трассировка непосредственно на VPS.

ИЗМЕНЕНИЯ
1. MP3-фон, уже работающий с -re / 25 fps, передаёт каждый полный кадр ровно один раз на протяжении всей песни. R1085 больше не выбрасывает и не дублирует эти кадры. Реальная обратная связь pipe/drain сохранена.
2. Убран R1160G phase rebase: счётчик отправленных кадров больше не переписывается после клипа. Фаза границы записывается в диагностику.
3. При R884-восстановлении нормальный фон возвращается в ту же ветку владения и темпа.
4. Сохранены 1080p25, H.264 6000k, GOP 50, B=0, AAC 44100 stereo 160k, очереди 96/96, две RTMPS-линии. PCM-пейсер клипов R1123 не изменён.
5. Из R1160K: асинхронный ffprobe, ограниченный кэш результатов, исключение трёх дополнительных копий 3.11 MB на кадр, исправление SIGTERM/SIGKILL и ожидания смены видеопроцесса, ограничение частоты диагностического спама.
6. Диагностика: PID, память процесса, реальные входные счётчики, очереди, ожидание drain, drop/dup, входная фаза. Это не измерение задержки у зрителя и не измерение FPS YouTube.
7. Агент R1183: CPU VPS из /proc, память, load average отдельно от CPU%, более полные инциденты, до 16 часов минутных метрик на диске. Файл: /var/cache/andrik-radio-r622/diagnostics/r1183-metrics-16h.json. На страницу приходят последние данные; история браузера собирается отдельно.

ПРОВЕРКИ
- Исходный вариант: воспроизведён стоп на 182 закодированных кадрах, PCM-очередь 67032 B, входная фаза 1900 мс, 214 отброшенных кадров к концу 17-секундного прогона.
- Исправленный вариант в том же сценарии: 392 закодированных кадра за 17 секунд, в конце обе очереди пусты, drop=0, dup=0. Искусственная ошибка счётчика внесена только в тест.
- Реальные функции relay: MP3 → клип → MP3, 26 секунд с FFmpeg 1080p25; после возврата в MP3 кадры продолжают идти примерно 25/с, drop=0, dup=0. Полный производственный планировщик, YouTube и сеть VPS этим тестом не проверены.
- Проверены асинхронный ffprobe, кэш, последовательность замены, завершение зависшего дочернего процесса и ограничение ошибок.
- Установщик: проверка, установка, повторный запуск без рестарта, отказ на чужом исходнике, ручной и автоматический откат. systemctl в проверке имитировался.
- 12–16 часов работы на VPS и реальная синхронизация у зрителя ещё не проверены. Этот архив сам по себе ничего на сервере не устанавливает.

ПОСЛЕ УСТАНОВКИ
В контрольке должны появиться agent R1183 и revision R1160L-MP3-CADENCE-REAL-COUNTERS.
Для короткого отчёта:
sudo python3 CHECK-ANDRIK-R1160L.py
Для проверки ночной работы:
sudo python3 CHECK-ANDRIK-R1160L.py --hours 16
Сборщик не перезапускает эфир, снимает процессы/CPU/очереди, журналы за 18 часов и минутную историю агента, маскирует RTMPS-адреса и секреты. ZIP с результатом сохраняется в текущей папке. Длительный запуск держи в своей обычной screen/tmux-сессии VPS, чтобы закрытие SSH его не прервало.
