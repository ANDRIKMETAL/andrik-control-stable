YOUTUBE VIEWS DAILY COUNTER
1. Audited the previous code: youtubeViewDelta was NOT a strict rolling 24-hour metric. It was the cumulative channel view delta from the active Bratislava 06:05 -> 06:05 summary window.
2. Found a durability defect: that delta depended on platform_snapshots; snapshots are trimmed, so the 06:05 baseline could disappear later in the day. High-water protection could then preserve/freeze an older maximum.
3. R410 persists one YouTube cumulative-view baseline per summary window in push_state.
4. Near 06:05, the first successful live YouTube identity fetch replaces a nearby snapshot baseline with the live rollover value.
5. When the R410 baseline is first created/replaced, only the old YouTube-view high-water fields for that window are cleared so a stale pre-R410 value cannot stay pinned.
6. Current-screen YouTube views use the durable live baseline directly; old push checkpoint values cannot reintroduce the retired transient baseline.
7. The counter therefore resets together with the other summary counters at the new 06:05 window and remains stable for the full day even after old snapshots are trimmed.
