ANDRIK SITE R1494 — ИСПРАВЛЕНИЕ ПРОВЕРКИ РЕАКЦИЙ YOUTUBE

Основа: приложенный полный SITE R1493. Обновление устанавливается обычным ZIP
через раздел обновления сайта в контрольке.

ЧТО ОБНАРУЖЕНО В R1493
1. В воспроизведённом спокойном цикле: 124 SQL-запроса без новых событий
   (в отдельном прогоне с инициализацией таблицы графика — 128).
   Причины: чтение отдельной записи и маркера для каждого видео, отдельные
   обращения для сообщений чата, повторная загрузка ответов на комментарии.
2. Ветка, называвшаяся пропуском квоты, продолжала обращаться к комментариям
   и LIVE-чату при повторных вызовах.
3. Проверка реакций была связана с расширенной проверкой числа зрителей,
   включая запасные запросы авторизации и статистики.
4. Таймер запроса прекращался после заголовков, до чтения тела JSON.
5. LIVE-чат повторно запрашивался с новым курсором даже при квоте/отказе
   доступа, а переходы курсора не учитывали неудачную отправку уведомлений.

ИСПРАВЛЕНИЕ
• Атомарное ограничение частоты: обычный полный цикл не чаще 110 секунд,
  что сохраняет обновление при штатном Cron раз в две минуты. Более частые
  дубли отсекаются до обращений к YouTube. Ручной fresh-запрос имеет защиту
  от наложения 30 секунд.
• Объединённое чтение и запись D1, повторное использование существующей схемы
  и форматтеров времени. В сопоставимом тесте: 124 → 23 SQL-запроса;
  повторный вызов: 1 SQL-запрос, 0 запросов к YouTube.
• Короткая отдельная проверка видео для реакций. Расширенная статистика
  зрителей обслуживается прежним отдельным сборщиком.
• До трёх видео с комментариями за быстрый цикл и до двух дополнительных
  запросов ответов. Непроверенные счётчики остаются на следующие циклы.
• Уведомления ограничены оставшимся временем и числом SQL-запросов.
  Порядок комментарии/лайки/чат чередуется, чтобы очередь одного вида
  не задерживала остальные. При большом числе событий часть отправок
  переносится на последующие циклы.
• Комментарии, ответы и сообщения чата сохраняются в D1 до продвижения
  курсоров. Неотправленные события остаются в очереди. Лайк подтверждается
  изменением базового счётчика только после принятой отправки.
• Соблюдается pollingIntervalMillis. Закрытый/отключённый чат считается
  нормальным неактивным состоянием. Для ошибок квоты и частоты действует
  пауза; причина остаётся видимой. Неверный курсор сбрасывается отдельно.
• Таймеры запросов охватывают также чтение JSON; уведомления реакций
  не запускают длинную цепочку немедленных сетевых повторов.
• Служебное → Расписание и синхронизация показывает R1494, результат
  последней проверки и число отложенных событий.

УСТАНОВКА И ПРОВЕРКА
1. Установить этот полный ZIP обычным установщиком сайта.
2. После завершения обновления заново открыть раздел «Расписание и
   синхронизация». В диагностической строке должно быть R1494.
3. Включить «Реакции YouTube: лайки, комментарии и LIVE-чат».
   Прочие ранее выбранные галочки сохраняются автоматически.
4. Оставить штатный Cron раз в две минуты. Через 2–3 цикла проверить
   результат в контрольке и новые события Cloudflare за время ПОСЛЕ установки.
   Старые красные события остаются в истории; они не удаляются патчем.

ПРОВЕРКИ
28 автоматических проверок пройдены на Node.js VM + настоящем SQLite.
Внешние ответы YouTube и OneSignal заменялись тестовыми; реальных уведомлений
тесты не отправляли. Проверены ограничение 50 SQL-запросов, параллельные дубли,
200 сообщений чата, очереди и повторные отправки, неполадки квоты/курсоров,
первые лайки новых релизов, холодный запуск, таймауты тела ответа и DST.

ПРАКТИЧЕСКИЙ ПРЕДЕЛ ПРОВЕРКИ
По приложенному скрину не видны outcome/код/CPU-время конкретной красной
записи Cloudflare. Избыточная работа и перечисленные дефекты воспроизведены
на исходном коде; точный тип ошибки рабочего Cloudflare и исчезновение
красных событий нужно подтвердить после установки по новым журналам.
Node.js/SQLite не воспроизводят ограничение CPU рабочего Cloudflare.
