ANDRIK CONTROL · R1155 QUEUE NEXT
2026-09-23

ROOT CAUSES FOUND
1) Search/select already sent action queue-pick-r989 through Cloudflare Worker and the OVH agent,
   but the live radio server had NO /control/queue-pick-r989 endpoint. The command therefore
   ended at the local radio with "unknown local control" and could not change the queue.
2) The three-dot "Поставить следующей" UI moved an item upward by sending several independent
   remote commands in a tight loop. The command queue permits one active command, so the second
   move could collide with command-busy. An item from position 3/4/5 therefore was not reliably
   moved to position 1.
3) The picker intentionally filtered bumper/special MP4 files out, so station IDs could not be
   searched or manually placed next.

R1155 FIX
- One atomic queue operation: direction=next moves any visible queue item directly to #1.
- New live radio local endpoint /control/queue-pick-r989.
- Search/select can insert or move any library MP3 to #1.
- Search/select can insert or move normal clips, radio bumpers and 30/60-minute specials to #1.
- Main queue search now searches songs + clips + bumpers + specials from one dialog.
- Clips KPI picker now includes station material instead of hiding it.
- A manual "next" is authoritative for one boundary: automatic 30m/60m/bumper insertion cannot
  jump in front of the owner-selected item.
- Queue status uses the real first-future index during timed station inserts.
- Manually played bumper/special updates its normal cadence only after it actually reaches LIVE.

UNCHANGED
- Audio/PCM timing
- R1085/R1123 sync logic
- R1154 actual-next-owner fix
- H264/AAC/RTMPS transport
- Current media is never interrupted by queue editing
