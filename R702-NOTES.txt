R702 — MP3 HANDOFF + AUTO FIT FINAL

ROOT CAUSE FIXED
- R693 MP3 cache cleanup wrote FFmpeg output to a temporary filename without a .mp3 extension and without an explicit MP3 muxer. Fresh MP3 cache jobs could therefore fail and the queue skipped MP3 tracks, eventually returning to video clips.
- R702 writes the cleaned cache to *.mp3 and explicitly uses -f mp3.

CLIP -> MP3
- The following MP3 must be fully local before a video clip is allowed to start.
- At clip end the title immediately changes from КЛИП to the next MP3 title.
- DAY / EVENING / NIGHT visual resumes on the same persistent YouTube publisher.
- A local silence bridge keeps the master audio clock alive for the tiny handoff window.
- Video end is watched by actual frame progress plus the video-stream duration, so longer audio/container metadata cannot freeze the final video frame.

VIDEO
- Permanent rule: upload MP4 as-is. No manual stretching/resizing is required.
- Complete source frame is AUTO-FIT to 1920x1080 with aspect ratio preserved.
- crop/cover is OFF.

CACHE
- R2 dynamic clips already use uploaded-version URLs.
- JOY OF BEING now also receives an R2 uploaded timestamp in its URL, so replacing the source cannot leave an old local cached clip forever.

DEPLOY
After deploying the site, run the one R702 installer command shown in radio-visuals-admin.html.
