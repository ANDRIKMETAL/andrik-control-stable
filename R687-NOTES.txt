R687 — RADIO SELF-HEAL LIVE BIND
Base: R686

1) Fixed the one-tap Radio START path when an old YouTube broadcast has ended or the current CREATED broadcast is bound to the wrong stream.
2) New owner-only endpoint /api/control/youtube-live-r687/ensure discovers the ACTIVE YouTube liveStream that the OVH encoder is actually publishing to. No YouTube stream key is copied into Cloudflare.
3) If an editable CREATED/READY broadcast exists, R687 re-binds it to that ACTIVE stream. If none can be reused, R687 creates a new public ANDRIK METAL RADIO 24/7 broadcast and binds it automatically.
4) R687 transitions the exact bound broadcast to LIVE instead of relying on the old generic current-broadcast selector.
5) The Control START button now: restart/start OVH encoder -> wait for ACTIVE YouTube stream -> bind/create broadcast -> LIVE.
6) R658 remains supported for START via its safe native restart command. R665 is still preferred but is not required just to recover the broadcast.
7) A phone reboot/closing the Control page still has no STOP or unload hook and does not intentionally stop OVH. The stream lifecycle is server-side.
8) Existing R686 emoji push fix and all other site/control functions are preserved.
9) Added cache-reset-v55-00-final-r687.html; it preserves push/service workers and opens Radio Control directly.
