ANDRIK R1535 — GUARD CPU HISTORY + WATCH AUDIO CHECK

Сайт: полный ZIP загружается через «Обновить сайт» с резервной копией.
На VPS: отдельно обновить файлы GUARD и WATCH. Установка не трогает службу andrik-radio.service.

GUARD: хранит последние 60 минут CPU (среднее и максимум за 5/15/60 минут) в /var/lib/andrik-guard-r1531/cpu-history.json. Первые 15 минут история неполная. MANAGER создаёт задачу о длительной высокой загрузке при >=4 замерах за 15 минут со средним >=90%.

WATCH: по умолчанию аудиопроверка НЕ настроена (это честно отображается в контрольке). Для проверки звука нужен локальный HTTP(S) URL 127.0.0.1/localhost, выдающий реальный поток с аудио. Проверка через ffmpeg 4 секунды не чаще раза в 2 минуты, тревога после трёх подряд подтверждений тишины (около 6 минут). Пробы не работают для публичных адресов. Намеренная тишина в треках может давать предупреждения. Не устанавливать URL, пока не подтверждён правильный локальный поток. Проблемы со звуком не запускают перезагрузку.

Включение аудио: sudo systemctl edit andrik-watch-r1532.service
Добавить:
[Service]
Environment="ANDRIK_WATCH_AUDIO_URL=http://127.0.0.1:8080/ПРОВЕРЕННЫЙ_ЛОКАЛЬНЫЙ_ПОТОК"
Заменить адрес на реальный локальный аудиопоток; /status (JSON) НЕ подходит.
После сохранения: sudo systemctl daemon-reload && sudo systemctl start andrik-watch-r1532.service

Не требуется OpenAI API. MANAGER не выполняет команды на VPS, только предлагает и фиксирует решения.
