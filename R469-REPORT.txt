R469 — EXACT LIVE YOUTUBE DAILY COUNTERS SAFE FULL

Base: production R468 + R466 installer backup hotfix.

ROOT CAUSE FOUND IN R468
1. The */2 fast YouTube engagement path was already seeing real per-video like counts,
   but it did not persist an independent daily live-like accumulator.
2. The */5 subscriber path replaced youtube-counts-last-summary with only subscribers/views,
   silently erasing likesTotal/commentsTotal from the checkpoint.
3. R468 tied the live view baseline to a snapshot that also needed a valid likesTotal.
   If likesTotal was absent/incompatible, the views card could fall back to 0 too.

R469 FIX
1. Active-day likes are accumulated from observed per-video public like-count increases.
   This is independent of OneSignal push delivery and cannot be inflated by old high-water.
2. Mid-day migration bootstraps only from confirmed same-window YouTube-like deltas.
3. The fast like rotation now covers up to 200 remembered videos while still requesting
   only 24 videos per */2 cycle (no extra per-cycle API request).
4. The */5 subscriber checkpoint preserves existing likesTotal/commentsTotal.
5. Active-day views use a strict VIEW-ONLY 06:05 baseline, independent of likesTotal.
6. A stale current-fallback baseline far from 06:05 is rejected; the nearest real
   platform snapshot around 06:05 is used instead.
7. At exactly 06:05 Bratislava, one daily */5 job captures channel views and all tracked
   video like counters as the clean rollover baseline for the new day.
8. Completed/archive days still use the R467 exact YouTube Analytics calendar-day row.
9. Cron secrets, maps, music, subscriptions, player, monitoring and installer logic are unchanged.

Note:
- The current day on the first R469 install is reconstructed from confirmed same-window
  like history plus live observations. From the next 06:05 rollover onward, the baseline
  is captured natively by R469.
